# Applied Agentic AI — 12-month learning path

**Suggested cadence:** 5–7 hours per week, flexible; months are checkpoints rather than deadlines.

| Month | Core learning | Minimum build evidence |
|---|---|---|---|
| 1 | Context engineering; controlled AI-assisted coding | Context audit, schema-validated technical outline, four fixtures and baseline measurements |
| 2 | Python tools, typed models, retrieval boundaries | Single read-only tool-using assistant with trace and denied unsafe action |
| 3 | State machines, approvals, checkpoints, retries | Persist and resume a deterministic workflow; prove idempotency and approval rejection |
| 4 | Source provenance, RAG, document trust | Source manifest, dated claim ledger and contradictory-source tests |
| 5 | Code generation with execution-based verification | Run the lesson's example code in a sandbox, record pinned environment and test output |
| 6 | AI media fundamentals; scene composition | 30–60s pilot with fixed references, accurate authored technical diagrams and timed captions |
| 7 | Agent evaluations, costs and alternatives | Held-out comparison: deterministic vs one agent vs multi-agent |
| 8 | Durable orchestration and observability | Trace export, retries, checkpoint restore and failure replay |
| 9 | Production security, permissions and safety | Threat model, scoped identities, redaction tests and human release approval gate |
| 10 | Technical storytelling for career development | Two reviewed public case studies with runnable repositories and ADRs |
| 11 | Reusability and operational economics | Process a second episode; compare intervention, quality, runtime and cost |
| 12 | Personal and professional review | Skills audit, independent demo, role alignment and a decision to continue/pivot |

## Quarterly gates

### Month 3 — Understand and control

Demonstrate a bounded tool call, valid structured outputs, an unsafe action denied by policy, a persisted state transition, and a truthful statement of when deterministic functions beat an agent. No polished video required.

### Month 6 — A trustworthy vertical slice

One short pilot assembled from approved sources and tested code, with a human-approved script, correctly labelled diagram, timed subtitles and a reproducible rendering manifest. Natural lip-sync remains experimental until actually tested.

### Month 9 — Engineering, not demonstrations

Quantify success/failure, manual intervention, latency, cost-per-accepted-output and security controls. Show crash recovery and reject an injected instruction from retrieved material.

### Month 12 — Portable engineering proof

Show two independent case studies that hiring panels can inspect and reproduce, plus a working demo and explicit architecture trade-offs. Reflect on enjoyment and career fit before considering productisation.

## Weekly learning loop

- **Learn (2h):** official documentation, one focused concept, version/date notes.
- **Build (3h):** a small runnable vertical slice.
- **Evaluate (1h):** happy path, failure path, cost or performance comparison.
- **Explain (1h):** learning log, commit, concise architecture decision and follow-up.

## Cost and hardware rule

Do not buy an expensive workstation as a prerequisite. Benchmark at least one representative video workload using an available machine and/or short-term rented GPU capacity. Compare local amortised cost with actual cloud usage and the cost per **accepted** shot, not just raw generation speed.
