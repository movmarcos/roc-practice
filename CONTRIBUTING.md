# Contributing

Keep the prompts useful across roles and technologies. Add technology examples as optional examples rather than mandatory dependencies.

For adapter changes, name the exact product, surface and version you exercised. Separate documented support, fixture tests and live verification. Include a minimal reproducible task and an explicit gap when a capability has no equivalent.

For experiment results, include the starting revision, conditions, model and tool versions, active instructions, run order, time budget, interventions and evidence. Keep unmeasured values empty. Never publish private project files, transcripts or credentials.

Run the Python and Node checks in the README. Change canonical capability content rather than editing generated files. Preserve source and licensing for third-party contributions.
